## Summary

- Scope: all 33 files of `/home/dean/code/llm-d/llm-d-scaling-manager/policy-writer` (`git ls-files`) were opened and read: 33 of 33. Cited line numbers are from `cat -n` of those files. - Counts by severity: 84 findings: 5 blocker (3 distinct problems: skills link, exclude command in two files, missions index), 53 fix, 26 nit.
- Top 1 (blocker): the `.claude/skills` dir-symlink design cannot work in any worktree cut from upstream `main`. That worktree has a real `.claude/skills/` with tracked `pr-review` (checked: `main/.claude/skills/pr-review/SKILL.md`). `conv-feature-worktree-setup` L60 then stops with "blocker" and sets up no skills. `resume-mission` Step 5b (L146-150) fails with "BROKEN". Fix: link each skill individually inside the real directory, or load skills from another place. The user has to choose.
- Top 2 (blocker): coder startup step d fails closed. `worktree-delegation.md` L55-61 and `conv-coder-orchestration` L68-72 append to `<common-dir>/worktrees/$WTID/info/exclude`. In this workspace the directory `repo/worktrees/policy-writer/` has no `info/` subdirectory (checked with `ls -la`), so `>>` fails and every coder launch aborts. Git also reads only `<common-dir>/info/exclude` for ignore rules, I believe (not tested here). Use `git rev-parse --git-path info/exclude` or the repo-wide file as `conv-feature-worktree-setup` does.
- Top 3 (blocker or decision): `resume-mission` Step 3 (L86) and 5c read `$TRACKING/missions/`, and the mission index, the suggestion box and the convenience symlinks all live in `session-tracking`. The task file says it is intentionally empty and nothing is written to it. Several rules contradict that: `conv-feature-worktree-setup` L126-161, `policy-writer.md` L34-35 and L56-75, `mission-owner.md` L49-56. Also, every "read `session-tracking/CONVENTIONS.md`" instruction fails until the first install. Needed: a user decision on the `missions/` index, plus a bootstrap line (read from `policy-writer/` until the first install).
- PR rules: no PR-related skill mentions the verified signature (`-S`), conventional commits, `make lint`/`make test` by name, or the merge queue. `conv-pr-branch` and `conv-pr-workflow` cite two GitHub MCP servers (`gh-public`, `gh-ibm`) that exist only in `~/.bob/settings/mcp.json`, not in Claude Code. No rule says how to update an open PR when the base moves (rebase is forbidden, a re-cut needs a force push, which the guard blocks). `conv-coder-orchestration` L135 has a PR-prep agent that rebases, against `CONVENTIONS.md` L111 and `conv-pr-branch` rule 1.
- Non-PR branches (`policy-writer`, `session-tracking`, `.session/`-only mission branches): no rule demands DCO or signatures of them. `conv-push` L26 says "DCO" with no scope, and `reviewer.md` L25 likewise. They should state that this applies to PR branches only.
- Harvester: all uses (`coder.md` L18-21, `resume-mission` L303-307, `wind-down` L84-97 and L124) match the real script (subcommands `register`, `close --wait`, `status`, `reopen`, `start-next` exist; exit codes 0/1/2/3/4 match). Only gap: `resume-and-handoff.md` omits it, and the ledger is described as hand-maintained (see CONVENTIONS L100).
- Layout: `resume-mission` L96 (`$(dirname "$TRACKING")/$MISSION_NAME`, siblings of session-tracking) is correct for the flat layout. No `worktrees/` path, `/home/dean/...` path (except `conv-background-agents` L26, which matches `repos.json`) or old project name was found in the review scope, except one test-name leftover (`tasks.md` L81).
- Ambiguities that need an answer: `git -C` allowed or forbidden (CONVENTIONS L16, `conv-working-outside-worktree` L15 against `resume-mission` L131, `conv-feature-worktree-setup`, `worktree-delegation` L109-116); `EnterWorktree` called or only "verified" (`resume-mission` L56 against L121); three names for a worker's task file (`task-<id>.md`, `STATE.coder`, `<slug>.STATE.md`).
